# Как мы ведём работу

Документ описывает договорённости по процессу. Правила для Claude Code продублированы
в сжатом виде в [CLAUDE.md](CLAUDE.md).

## Ветки

Ветка `main` всегда зелёная и готова к деплою. Прямые коммиты в неё запрещены,
это проверяет хук `.githooks/pre-commit` и правило защиты ветки на GitHub.

Имя ветки состоит из типа и короткого описания через дефисы:

| Префикс | Когда используется |
| --- | --- |
| `feat/` | новая функциональность |
| `fix/` | исправление ошибки |
| `refactor/` | изменение структуры без смены поведения |
| `docs/` | документация |
| `chore/` | инфраструктура, зависимости, CI |

Пример: `feat/user-import`, `fix/timezone-offset`.

## Коммиты

Формат Conventional Commits: `тип(область): краткое описание`.

```
feat(api): добавить эндпоинт экспорта
fix(parser): не падать на пустом вводе
chore(ci): поднять версию actions/checkout
```

Заголовок в повелительном наклонении, до 72 символов, без точки в конце.
Один коммит решает одну задачу. Тело коммита объясняет причину, а не пересказывает диф.

## Pull Request

1. Ветка от актуального `main`.
2. Коммиты с прохождением локальных проверок.
3. `gh pr create` с заполненным шаблоном.
4. Зелёный CI обязателен для слияния.
5. Слияние через squash, ветка удаляется после слияния.

PR решает одну задачу и остаётся обозримым. Если диф разрастается,
он делится на несколько PR.

## Проверки

Перед коммитом автоматически запускаются форматирование, линтер и тесты.
Те же проверки повторяет CI на Python 3.12 и 3.13.

```bash
uv run ruff format .
uv run ruff check .
uv run pytest
```

Хук можно обойти флагом `--no-verify`, но CI всё равно остановит слияние.

## Код

- Python 3.12, длина строки 100 символов.
- Аннотации типов на публичных функциях.
- Docstring там, где назначение не очевидно из имени.
- Новое поведение сопровождается тестом.
- Секреты только через переменные окружения, в репозиторий не попадают.

## Задачи

Работа заводится через issue по шаблону «Задача» или «Баг».
PR ссылается на issue строкой `Closes #N`.
